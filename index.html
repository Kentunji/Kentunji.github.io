Case study

Case study, client details anonymised

The daily build that failed on a key nobody had used yet

Problem

A client's daily infrastructure builds on AWS started failing with a KMS error. Rerunning the pipeline would have hidden it, and it would have come back.

What I did

I traced it through the AWS APIs and found two separate causes: an IAM race condition in the build, and the first use of an AWS managed KMS key for Secrets Manager. I fixed both and wrote a full incident report with a timeline and prevention steps.

The trap I avoided

Checking that key with describe-key actually creates it, which would have destroyed the evidence. The pre-check I wrote reads the key aliases instead, so it looks without changing anything.

Outcome

The builds were unblocked, and the client has a written record they can follow if a similar failure ever appears.
